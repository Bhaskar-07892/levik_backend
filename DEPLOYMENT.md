# Deploying the Levik staging environment

This sets up a hosted test environment, so the team and testers can use the admin portal and an Android APK without anyone's laptop running. Every push to `main` redeploys it automatically.

| Piece | Host | Deploys when | Cost |
| ----- | ---- | ------------ | ---- |
| API (this repo) | [Render](https://render.com) web service, Singapore | push to `main`, **after CI passes** | Free (sleeps after 15 min idle) |
| Database | Neon project `levik-staging`, Singapore | migrations run when the API starts | Free |
| Admin portal ([levik_admin_app](https://github.com/shubhamjoshi99899/levik_admin_app)) | [Vercel](https://vercel.com) | every push (`main` → live, other branches → preview URLs) | Free (Hobby) |
| Mobile app ([levik-mobile](https://github.com/shubhamjoshi99899/levik-mobile)) | [EAS](https://expo.dev/eas): APK once, then over-the-air updates | push to `main` publishes an update; installed APKs get it on next launch | Free tier |

```
git push ─► GitHub Actions CI (lint, typecheck, build, tests)
              ├─ levik-api    ─► passes ─► Render redeploys the API (migrations run at boot)
              ├─ levik-admin  ─► Vercel builds and deploys on its own
              └─ levik-mobile ─► passes ─► eas update ─► testers' APKs update on next launch
```

Do the steps in order: each one needs a URL from the one before.

## 1. Database: Neon `levik-staging`

1. In Neon, open (or create) the project `levik-staging` in AWS Singapore (`ap-southeast-1`).
2. On **Connect**, turn **Connection pooling off** and copy the **direct** connection string (host without `-pooler`). The API runs migrations at boot, and migrations need a direct connection.
3. Load the demo data once, from your laptop, in this repo:

   ```bash
   DATABASE_URL='<direct staging URL>' DB_SSL=true npm run migration:run
   DATABASE_URL='<direct staging URL>' DB_SSL=true npm run db:seed
   ```

Keep the URL out of chat, commits and screenshots. It goes only into Render (step 2).

## 2. API: Render

1. Sign in to Render with GitHub and allow it access to the `levik_backend` repository.
2. **New → Blueprint**, pick the repository and branch `main`. Render reads [`render.yaml`](render.yaml) and creates the `levik-api` service.
3. It asks for the values marked `sync: false`:
   - `DATABASE_URL`: the direct staging URL from step 1.
   - `CORS_ORIGINS`: put `http://localhost:3020` for now. You will add the Vercel URL in step 3.
4. Wait for the first deploy, then open `https://<service>.onrender.com/api/v1/health/ready`. It should report the database as `up`. Note the service URL: the admin portal and the app need it.

`JWT_ACCESS_SECRET` and `QR_SIGNING_SECRET` are generated by Render. Never change `QR_SIGNING_SECRET` after printing labels from this API, or those labels stop verifying.

**How deploys work:** Render watches `main` but deploys only when the GitHub Actions checks on that commit pass (`autoDeployTrigger: checksPass`). A failing commit leaves the previous version running. **Manual Deploy → Deploy latest commit** forces one.

**Free plan limits:**
- The service sleeps after 15 minutes without requests. The next request takes about a minute while it wakes up. Upgrade the service to **Starter** in Render to keep it awake.
- There is no persistent disk. Uploaded invoices and installation photos are lost on each deploy or restart. That is fine for testing, but real use needs object storage (S3 or Cloudflare R2 behind `StorageDriver`).

## 3. Admin portal: Vercel

1. In Vercel, **Add New → Project** and import `levik_admin_app` from GitHub. Vercel detects Next.js; keep the defaults.
2. Under **Environment Variables** add:
   - `NEXT_PUBLIC_API_URL` = `https://<service>.onrender.com` (no trailing slash, no `/api/v1`)
   - `NEXT_PUBLIC_SHOW_DEMO_LOGIN` = `true` (staging only)
3. **Deploy**, and note the URL, for example `https://levik-admin.vercel.app`.
4. Back in Render, set `CORS_ORIGINS` on `levik-api` to that URL, for example `https://levik-admin.vercel.app,http://localhost:3020`. Saving it redeploys the API.
5. Sign in with the demo admin (`admin@levik.demo` / `LevikDemo@123`).

`NEXT_PUBLIC_*` values are baked in at build time, so after changing one, redeploy in Vercel (**Deployments → … → Redeploy**).

## 4. Mobile app: APK and over-the-air updates

Run these in `levik-mobile`. You need a free [Expo account](https://expo.dev/signup).

```bash
npx eas-cli@latest login
npx eas-cli@latest init
npx eas-cli@latest update:configure
npx eas-cli@latest env:create --environment preview --name EXPO_PUBLIC_API_URL --value https://<service>.onrender.com --visibility plaintext
npx eas-cli@latest build --platform android --profile preview
```

- `init` creates the EAS project and adds its ID to `app.json`, and `update:configure` adds the update URL. **Commit both `app.json` changes.**
- The build runs in Expo's cloud and takes about 10–20 minutes. When it finishes, it prints a link and QR code: open it on an Android phone to download and install the APK. Allow "install unknown apps" for the browser when asked.
- The APK talks to the hosted API, so it works on any network.

**Updates after a push:**
- **Code changes:** for every push to `main` that passes CI, GitHub Actions runs `eas update` on the `preview` channel. Installed APKs download the update in the background and use it the **next time the app is opened** (fully close it and open it again).
- **Native changes:** an update cannot carry a new native module, a plugin or permission change in `app.json`, or an Expo SDK upgrade. Those change the app's [fingerprint](https://docs.expo.dev/versions/latest/sdk/fingerprint/) and need a new APK: run the `eas build` command again and reinstall.

**One-time GitHub setup for updates:** create an access token at expo.dev → Account settings → **Access tokens**, then add it to the `levik-mobile` repository on GitHub as an Actions secret named `EXPO_TOKEN` (**Settings → Secrets and variables → Actions**).

## Test accounts on staging

Staging runs with `APP_ENV=staging`. That keeps the test OTP `123456` for the seeded numbers (`98290 11234` plumber, `98290 41127` retailer, `99000 11122` new user) and the API docs at `/api/docs`. No real SMS is sent.

## Going to production later

Repeat the steps with a `levik-prod` Neon project, a second Render service and Vercel production domain, and an EAS `production` build. In production:
- Set `APP_ENV=production`. That turns off test OTPs and the docs.
- Set `SMS_PROVIDER=msg91` with its keys.
- Use object storage for uploads.
- Use a paid Render instance.
